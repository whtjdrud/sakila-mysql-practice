# FIX-014. 문자열로 정렬된 숫자

**유형:** 쿼리 디버깅 · **난이도:** ★★☆☆☆ 초급 · **태그:** `정렬` `형 변환` `CAST` `디버깅`

## 문제

**증상:** 우편번호가 **작은** 순서대로 5개를 뽑았는데 `1027`, `10417` … 이 나옵니다. 그런데 데이터에는 `3`, `400` 같은 더 작은 번호도 있습니다.

```sql
SELECT address_id, postal_code
FROM address
WHERE postal_code <> ''
ORDER BY postal_code
LIMIT 5;
```

**숫자 크기 기준**으로 작은 5개가 나오도록 고치세요. 같으면 `address_id` 순.

<details>
<summary>정답 쿼리 보기</summary>

```sql
SELECT address_id, postal_code
FROM address
WHERE postal_code <> ''
ORDER BY CAST(postal_code AS UNSIGNED), address_id
LIMIT 5;
```

</details>

<details>
<summary>실행 결과 보기</summary>

| address_id | postal_code |
|---|---|
| 445 | 3 |
| 523 | 400 |
| 346 | 504 |
| 554 | 841 |
| 577 | 943 |

> 총 5행

</details>

## 해설

**원인:** `postal_code` 는 VARCHAR 라 **사전 순**으로 정렬됩니다. 문자열에서는 첫 글자부터 비교하므로 `'1027' < '3'` 입니다 ('1' < '3').
우편번호 길이는 5자리 534개, 4자리 59개, 3자리 5개, 1자리 1개로 섞여 있어 이런 차이가 생깁니다.
**수정:** 숫자로 비교하려면 `CAST(... AS UNSIGNED)`. 다만 우편번호처럼 앞자리 0 이 의미 있는 코드는 원래 문자열이 맞는 타입입니다 — 정렬 목적에 따라 판단하세요.
