# SUB-032. 전월 대비 매출이 늘어난 매장

**유형:** 서브쿼리 · **난이도:** ★★★★☆ 고급 · **태그:** `파생 테이블 셀프 조인` `전월 비교`

## 문제

매장(`staff.store_id`)별 월 매출을 파생 테이블로 구한 뒤 **같은 파생 테이블과 셀프 조인**해 바로 전 달과 비교하세요.
2005-06 ~ 2005-08 만 대상입니다.

- 출력: `store_id`, `month`, `revenue`, `prev_revenue`, `growth_pct`(소수 1자리) — `store_id`, `month` 순

**사용 테이블:** `payment`, `staff`

<details>
<summary>정답 쿼리 보기</summary>

```sql
SELECT cur.store_id, cur.month, cur.revenue, prev.revenue AS prev_revenue,
       ROUND(100 * (cur.revenue - prev.revenue) / prev.revenue, 1) AS growth_pct
FROM (
    SELECT s.store_id, DATE_FORMAT(p.payment_date, '%Y-%m-01') AS month, SUM(p.amount) AS revenue
    FROM payment p JOIN staff s ON s.staff_id = p.staff_id
    GROUP BY s.store_id, month
) cur
JOIN (
    SELECT s.store_id, DATE_FORMAT(p.payment_date, '%Y-%m-01') AS month, SUM(p.amount) AS revenue
    FROM payment p JOIN staff s ON s.staff_id = p.staff_id
    GROUP BY s.store_id, month
) prev ON prev.store_id = cur.store_id
      AND prev.month    = DATE_FORMAT(cur.month - INTERVAL 1 MONTH, '%Y-%m-01')
WHERE cur.month BETWEEN '2005-06-01' AND '2005-08-01'
ORDER BY cur.store_id, cur.month;
```

## 해설

"전월" 을 행 순서가 아니라 **날짜 연산(`- INTERVAL 1 MONTH`)** 으로 찾기 때문에 중간에 빈 달이 있어도 잘못 비교하지 않습니다.
`LAG()` 는 "직전 행" 을 가져오므로 빈 달이 있으면 2달 전과 비교하는 실수를 할 수 있습니다 — 두 방식의 차이를 기억하세요.
