# 003. 매장별 월간 매출

**난이도:** ⭐⭐ 중

## 문제

매장(store)별, 월별 결제 합계와 결제 건수를 구하세요.

- 출력 컬럼: `store_id`, `month`(YYYY-MM), `payments`(건수), `revenue`(합계)
- 매장 → 월 순으로 정렬

**힌트:** 결제(`payment`)는 처리한 직원(`staff`)을 통해 매장과 연결됩니다.

**사용 테이블:** `payment`, `staff`

## 풀이 쿼리

```sql
SELECT s.store_id,
       DATE_FORMAT(p.payment_date, '%Y-%m') AS month,
       COUNT(*)                             AS payments,
       SUM(p.amount)                        AS revenue
FROM payment p
JOIN staff s ON s.staff_id = p.staff_id
GROUP BY s.store_id, month
ORDER BY s.store_id, month;
```

## 분석

### 핵심 개념
- `payment` 에는 `store_id` 가 없어서 **결제를 처리한 직원(`staff`)의 소속 매장**으로 연결했습니다. (고객의 매장 `customer.store_id` 로 연결하면 다른 결과가 나옵니다 — 문제의 "매장 매출" 정의를 먼저 정하는 것이 중요합니다.)
- `GROUP BY ... month` 처럼 SELECT 의 별칭을 GROUP BY 에 쓰는 것은 MySQL 의 확장 문법입니다. 표준 SQL 에서는 `DATE_FORMAT(...)` 식을 그대로 다시 써야 합니다.

### 결과 해석
- 전체 매출은 **67,416.51** (16,049건). 두 매장의 매출은 거의 반반입니다.
- **2005-07 이 정점**(두 매장 합 28,373.89)이고, 데이터 기간은 2005-05-24 ~ 2006-02-14 입니다.
- 2005-09 ~ 2006-01 은 **데이터가 아예 없고**, 2006-02 는 단 하루(2/14)분입니다. 이날 대여 182건 대부분은 반납되지 않았습니다(미반납 전체 183건).
- 따라서 "2006-02 매출 급감"은 실제 추세가 아니라 **데이터 수집 기간의 경계** 때문입니다. 시계열 분석 전에는 항상 `MIN/MAX` 날짜와 빈 구간을 먼저 확인하세요.

### 더 해보기
- 빈 달도 0으로 표시하려면 재귀 CTE 로 월 목록을 만든 뒤 `LEFT JOIN` 합니다.
