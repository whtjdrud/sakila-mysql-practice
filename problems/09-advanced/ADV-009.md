# ADV-009. 고객 생애 가치 예측용 피처 테이블

**유형:** 복합 분석 · **난이도:** ★★★★★ 최고급 · **태그:** `피처 엔지니어링` `다중 CTE` `기간 분리`

## 문제

5~6월 행동으로 7~8월 결제액을 예측하는 모델을 만든다고 할 때, 고객별 **피처**와 **정답(label)** 테이블을 만드세요.
고객 1~10번만 출력합니다.

- 피처(2005-05-01 ~ 2005-06-30): `f_rentals`(대여 수), `f_paid`(결제액), `f_categories`(빌린 장르 수), `f_avg_rate`(평균 대여료, 소수 2자리)
- 정답(2005-07-01 ~ 2005-08-31): `label_paid`(결제액, 없으면 0)

출력: `customer_id`, `f_rentals`, `f_paid`, `f_categories`, `f_avg_rate`, `label_paid` — `customer_id` 순

**사용 테이블:** `rental`, `payment`, `inventory`, `film`, `film_category`

<details>
<summary>정답 쿼리 보기</summary>

```sql
WITH feat_r AS (
    SELECT r.customer_id, COUNT(*) AS f_rentals,
           COUNT(DISTINCT fc.category_id) AS f_categories,
           ROUND(AVG(f.rental_rate), 2) AS f_avg_rate
    FROM rental r
    JOIN inventory i      ON i.inventory_id = r.inventory_id
    JOIN film f           ON f.film_id      = i.film_id
    JOIN film_category fc ON fc.film_id     = f.film_id
    WHERE r.rental_date >= '2005-05-01' AND r.rental_date < '2005-07-01'
    GROUP BY r.customer_id
), feat_p AS (
    SELECT customer_id, SUM(amount) AS f_paid
    FROM payment
    WHERE payment_date >= '2005-05-01' AND payment_date < '2005-07-01'
    GROUP BY customer_id
), label AS (
    SELECT customer_id, SUM(amount) AS label_paid
    FROM payment
    WHERE payment_date >= '2005-07-01' AND payment_date < '2005-09-01'
    GROUP BY customer_id
)
SELECT c.customer_id,
       COALESCE(fr.f_rentals, 0)    AS f_rentals,
       COALESCE(fp.f_paid, 0)       AS f_paid,
       COALESCE(fr.f_categories, 0) AS f_categories,
       fr.f_avg_rate,
       COALESCE(l.label_paid, 0)    AS label_paid
FROM customer c
LEFT JOIN feat_r fr ON fr.customer_id = c.customer_id
LEFT JOIN feat_p fp ON fp.customer_id = c.customer_id
LEFT JOIN label l   ON l.customer_id  = c.customer_id
WHERE c.customer_id <= 10
ORDER BY c.customer_id;
```

## 해설

머신러닝 데이터 준비의 핵심은 **피처 기간과 정답 기간을 엄격히 분리**하는 것입니다. 정답 기간의 정보가 피처에 섞이면(데이터 누수) 모델이 과대평가됩니다.
고객 테이블을 기준으로 LEFT JOIN 해서 활동이 없는 고객도 0으로 남겼습니다 — 0도 중요한 학습 데이터입니다.
