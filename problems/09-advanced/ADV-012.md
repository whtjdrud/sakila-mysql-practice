# ADV-012. 세션화 (30분 규칙)

**유형:** 복합 분석 · **난이도:** ★★★★★ 최고급 · **태그:** `세션화` `LAG` `누적합`

## 문제

한 고객의 대여 사이 간격이 **30분 이하**이면 같은 방문(세션)으로 봅니다.
고객 1~50번의 세션 수와 세션당 평균 대여 수를 구하고, 세션당 대여가 가장 많은 고객 5명을 출력하세요.

- 출력: `customer_id`, `rentals`, `sessions`, `rentals_per_session`(소수 2자리)
- `rentals_per_session` 내림차순, `customer_id` 순

**사용 테이블:** `rental`

<details>
<summary>정답 쿼리 보기</summary>

```sql
WITH g AS (
    SELECT customer_id, rental_id, rental_date,
           CASE WHEN TIMESTAMPDIFF(MINUTE,
                     LAG(rental_date) OVER (PARTITION BY customer_id ORDER BY rental_date, rental_id),
                     rental_date) <= 30
                THEN 0 ELSE 1 END AS new_session
    FROM rental
    WHERE customer_id <= 50
), s AS (
    SELECT customer_id,
           SUM(new_session) OVER (PARTITION BY customer_id ORDER BY rental_date, rental_id ROWS UNBOUNDED PRECEDING) AS session_no
    FROM g
)
SELECT customer_id, COUNT(*) AS rentals, COUNT(DISTINCT session_no) AS sessions,
       ROUND(COUNT(*) / COUNT(DISTINCT session_no), 2) AS rentals_per_session
FROM s
GROUP BY customer_id
ORDER BY rentals_per_session DESC, customer_id
LIMIT 5;
```

## 해설

웹 로그 분석의 **세션화**와 같은 기법입니다: ① 이전 이벤트와의 간격으로 "새 세션 시작" 플래그 → ② 플래그 누적합 = 세션 번호.
첫 대여는 LAG 가 NULL 이라 CASE 의 ELSE 로 빠져 새 세션(1)이 됩니다 — NULL 처리가 의도대로 되는지 항상 확인하세요.
두 윈도우(LAG, 누적합)의 정렬 기준을 **똑같이** `rental_date, rental_id` 로 맞춰야 같은 시각 대여에서도 세션 번호가 흔들리지 않습니다.
