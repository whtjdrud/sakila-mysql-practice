# BIZ-012. 고객 등급제 시뮬레이션

**유형:** 실무 요청 · **난이도:** ★★★☆☆ 중급 · **태그:** `등급` `CASE` `매출 비중`

## 문제

> **요청자:** CRM팀 · **용도:** 멤버십 등급 기준 검토

누적 결제액으로 등급을 나눴을 때 등급별 인원과 매출 비중을 보고 싶습니다.

| 등급 | 누적 결제액 |
|---|---|
| PLATINUM | 180 이상 |
| GOLD | 140 이상 |
| SILVER | 100 이상 |
| BRONZE | 그 외 |

**요구 컬럼:** `tier`, `customers`, `customer_pct`, `revenue`, `revenue_pct` (% 는 소수 1자리)

**정렬:** PLATINUM → GOLD → SILVER → BRONZE

<details>
<summary>정답 쿼리 보기</summary>

```sql
WITH t AS (
    SELECT customer_id, SUM(amount) AS paid,
           CASE WHEN SUM(amount) >= 180 THEN 'PLATINUM'
                WHEN SUM(amount) >= 140 THEN 'GOLD'
                WHEN SUM(amount) >= 100 THEN 'SILVER'
                ELSE 'BRONZE' END AS tier
    FROM payment
    GROUP BY customer_id
)
SELECT tier, COUNT(*) AS customers,
       ROUND(100 * COUNT(*) / SUM(COUNT(*)) OVER (), 1) AS customer_pct,
       SUM(paid) AS revenue,
       ROUND(100 * SUM(paid) / SUM(SUM(paid)) OVER (), 1) AS revenue_pct
FROM t
GROUP BY tier
ORDER BY FIELD(tier, 'PLATINUM', 'GOLD', 'SILVER', 'BRONZE');
```

</details>

## 해설

등급 기준을 정할 때는 **"상위 등급이 인원의 몇 %, 매출의 몇 %"** 인지가 핵심 판단 자료입니다. 인원 대비 매출 비중이 클수록 등급 혜택의 효율이 좋습니다.
기준값만 바꿔 여러 번 돌려 보며 비교하는 시뮬레이션에는 CASE 를 CTE 한 곳에 모아 두는 구조가 편합니다.
